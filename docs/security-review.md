# Security and secrets review (Slice 4 hardening)

Scope: the FLOW HQ server, its booking API and staff API, the audit outbox, the n8n workflow candidate (4C), the compose / Caddy configuration in the repo, secrets handling, dependencies. Method: reading the code and configuration, plus tests against real Grist, a real n8n, a real Caddy and the real production image (`docs/staging-environment.md`). **Not done:** a review of the live VPS, the live n8n or the live Grist (no access); a penetration test; a review of Meta / Google account settings.

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| S1 | **HIGH** (configuration) | The Caddyfile that `flowhq/deploy/docker-compose.flowhq.yml` mounts proxies **everything** on the n8n domain, so the **n8n editor, its REST API and the test webhooks are on the public internet**, and the **n8n-only booking API** (`/api/booking/*`) is public on the FLOW HQ domain. Switching it is a deployment step (it needs two new variables) |

## What was checked and held up
- **Secrets in the repository:** `.gitignore` excludes `.env*` (except examples), `*.local.json`, `credentials.import.*`, `*.grist`, backups; `flowhq/.gitignore` excludes `config/users.json`, `config/booking-tokens.json`, `config/audit-outbox/`. Only variable **names** were read from `.env` files. The workflow candidate files carry credential **ids and names**, no values (`final.test.js`, `diff-workflows.js` refuse a secret-looking value).
- **Tokens:** only SHA-256 hashes are stored; `401` for missing / malformed / unknown / revoked / expired alike with identical bodies (tested in a real process); 20 failed attempts per real client address then `429`; scopes enforced; **no scope can record consent**; AI / n8n cannot call staff routes (cookie + CSRF + role required, tested in a real process).
- **Staff boundaries** (real process): front desk cannot change the AI switch or read the audit log; doctors only their own appointments; consent Yes needs an explicit grant; correction and revocation are admin-only.
- **Single process:** a second process on the same audit outbox is refused (503 `audit_unavailable`, nothing written) while the first keeps working (real process test). This enforces one writer **per outbox volume**; it is not a distributed lock.
- **Persistent volume:** the production image refuses the outbox on the container's own layer (503 + red health + a log line), keeps it across container re-creation on a named volume (same volume id), and exits `0` on `docker stop` within the 30 s grace period releasing the lock (all on the real image).
- **Audit content:** no patient name, phone, free text, idempotency key or secret (asserted against real `Booking_Audit` rows).
- **Consent:** AI / n8n can never turn Unknown into Yes; opt-out beats everything; an unreadable consent table suppresses reminders (all enforced both in FLOW HQ and in W12 / W5 / W15).
- **Logging:** the Grist client masks `Bearer …` and the API key in its error log; staging scripts never print keys (asserted for the credential creation step).

## Residual risks the owner should know about
1. Until S1's file is deployed, the n8n editor is internet-reachable (login-protected only). This is a property of the **current** repo configuration; the live server may already differ (unknown).
2. `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` is required by the workflows: every editor user can read every `FLOWHQ_*` variable (but not credential values). Keep editor accounts to the owner and one agency admin.
3. The AI model sees masked text only (the redaction layer), but the clinic's knowledge base is sent as is: never put patient data in the Knowledge table.
4. Meta, Google (Grist sign-in), OpenRouter and Cal.com account security are outside this repository.

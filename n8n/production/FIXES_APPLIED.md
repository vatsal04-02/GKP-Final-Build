# FIXES APPLIED

Generated by `tools/report.js` from `audit/changes.generated.json` (the change log written by `apply-production-hardening.js` while it builds the export).

## How the export is made (and how to redo it)

```
node n8n/production/apply-production-hardening.js --in <upload or redacted copy> --out n8n/production/clinic-autopilot-production.json
```

* It starts from the uploaded workflow (the private original, or `backup/…redacted.json`: the output is the same, the steps replace every secret by an environment expression).
* Existing logic is **not rebuilt**: the repository's own fingerprint-checked patcher (`n8n/integrated/apply-w2-signature.js`) runs first, then steps `steps/01…12` edit the workflow with **anchored** edits: every edit states the exact text it expects, and if the workflow does not match (a node edited in n8n, a step applied twice) the script stops and writes nothing.
* Output: 419 nodes (upload: 323), inactive, id `FhqClinicProd001`, no secret. Deterministic: the same input gives byte-identical output.
* Originals are kept: `backup/ai_updated_workflow_clinic_final_v3_v1.original.local.json` (private: contains the live secrets, git-ignored, mode 600) and `backup/…redacted.json`.

## Changes, step by step

### Step 01 — Configuration, secrets, guards, exposure, identity

* removed "W4 – Webhook" (POST /webhook/cal-w4-test): unauthenticated, connected to nothing, an unauthenticated public path with no purpose
* "W13 – Ask Model": removed allowUnauthorizedCerts (TLS certificates are always verified)
* W12 – Config: w12_uncertain_counts_as_sent=false (an unconfirmed Meta call is never reported as sent)
* Config nodes now read FLOWHQ_GRIST_URL, FLOWHQ_REGISTRY_DOC_ID, FLOWHQ_TEST_PHONE, FLOWHQ_CAL_WEBHOOK_SECRET, FLOWHQ_META_VERIFY_TOKEN, FLOWHQ_TELEGRAM_CHAT_ID, FLOWHQ_WA_SEND_MODE/ALLOWLIST/GRAPH_VERSION, FLOWHQ_AI_MODEL/EXTERNAL_ENABLED/MAX_REPLIES_PER_HOUR from the environment; no literal secret or identifier remains
* W2 – Signature Config: meta_app_secret from FLOWHQ_META_APP_SECRET (signature mode stays "enforce"; there is deliberately no environment switch to turn it off)
* W12 – Test input: removed a real Grist doc id, a WhatsApp phone-number id and a real test phone number (placeholders now)
* quiet hours: DISABLE_QUIET_HOURS_FOR_TEST switched back to false in 7 nodes (W12 Prepare request, W13 Build Context, W13 Plan Ready, W7/W8 Decide send, W9 Owner message, W10 Check): no patient message between 21:00 and 08:00 IST
* W11 – Format alert: skips the Telegram call when FLOWHQ_TELEGRAM_CHAT_ID is not set
* added Config Guard nodes (W1, W2, W2 verify, W2 signature, W3, W4, W5, W6, W7, W8, W9, W10, W12, W13): missing/placeholder settings stop the run with a message naming the variable
* 97 credential references renamed to stable ids/names: FlowHQ Grist API, FlowHQ W1 Webhook Auth, FlowHQ WhatsApp Cloud API, FlowHQ AI Provider, FlowHQ Telegram Alerts (scripts/create-credentials.js creates them from the environment)
* export identity: id FhqClinicProd001 (cannot overwrite the live workflow on import), inactive, timezone Asia/Kolkata, success executions not stored (patient data), failed executions stored, 15-minute timeout

### Step 02 — External AI gate and privacy filter

* W13 – Build Context: the AI route is closed unless FLOWHQ_AI_EXTERNAL_ENABLED=true (default off); a closed gate is the same quiet skip as ai_mode=off, nothing is sent to any provider
* W13 – Provider Request/Answer: patient name, phone, e-mail and long digit runs are masked before the request leaves (clinic rules, knowledge base and dates are untouched); a request whose shape is unexpected, or that still holds the phone digits, is not sent
* W9: new "W9 – External AI?" gate; when external AI is not enabled the metrics are never sent to the provider and the report is written from the numbers alone

### Step 03 — W12: uncertain state, send ledger (idempotency), callback data, template policy

* W12 – Prepare request / Read reply: "uncertain" is a state of its own (sent=false, uncertain=true), no longer counted as sent and never re-sent automatically
* W12 – Prepare request: idempotency key required (idem_key, or booking_uid / inbox_row_id / message_row_id / week); Meta receives biz_opaque_callback_data="fhq:<key>"; hello_world refused unless FLOWHQ_WA_ALLOW_HELLO_WORLD=true; template language from FLOWHQ_WA_TEMPLATE_LANGUAGE
* W12 send ledger: new nodes Ledger lookup/decide/Stopped by ledger?/claim/verify/winner/Won claim?/Row to release?/release/result/update/restore. Claim BEFORE calling Meta; duplicates and ledger outages return without calling Meta; Return result now carries uncertain, duplicate and idem_key

### Step 04 — W3/W5/W6: approved templates, idempotency keys, honest sent flag and logs

* W3 Build Message: hello_world -> new_lead_staff_alert; W5: hello_world -> reminder_24h / reminder_2h (and the literal Grist URL -> W5 – Config); W6: hello_world -> followup_day2 (needs booking_link); idem_key on every message
* W13 – Plan Ready: idem_key W13:<kind>:<inbound message row> on every send item
* W3/W5/W6 "Sent?" now means handled (sent, uncertain or duplicate): the flag is set, so an uncertain send is never retried; Run_Log is honest (ok / skipped / failed with the reason); rejected or invalid sends are logged (new nodes "Failed send to log?", "Prepare failed log", "Write failed log")

### Step 05 — W2: delivery receipts update the send ledger and the Messages status

* W2: delivery receipts (sent/delivered/read/failed) are parsed into status_events and update Send_Ledger (by callback data fhq:<key>, else WA_Message_ID) and Messages.Status; statuses only move forward; a failed delivery is logged in Run_Log (13 new nodes, second branch after the message branch)

### Step 06 — E.164 phone numbers (international)

* 18 Code nodes: the +91-only phone function is replaced by an E.164 normaliser (international numbers accepted; default country FLOWHQ_DEFAULT_COUNTRY_CODE, India if unset)

### Step 07 — W1: respond after storing, validation, consent, real staff alert

* W1: webhook now answers via Respond to Webhook AFTER storing (200 ok/duplicate, 400 invalid with reason, 404 unknown clinic; honeypot 200); consent + optional e-mail captured on the lead; the staff-alert stub is replaced by Alert settings -> plan (send guard) -> W12 (new_lead_staff_alert, idempotency key) -> honest Run_Log

### Step 08 — W4: raw-body HMAC, replay window, respond after the outcome, real confirmation

* W4 – Verify & parse: HMAC over the raw body (Raw Body option), 401 without alert for signature problems, replay window (createdAt); W4 – Resolve clinic carries wa_phone_number_id; leads created by a booking carry consent
* W4: answers via Respond to Webhook after the outcome (401 / 422 / 404 / 200; Grist failure = 500); the confirmation stub is replaced by Confirm item -> W12 (booking_confirmation, key W4:booking_confirmation:<uid>:<start>) -> Confirm_Sent + honest Run_Log

### Step 09 — Consent gate in W12; consent recorded for inbound WhatsApp leads

* W12: consent gate (Consent needed? / Lead consent / Consent decide / Consent stop?): a business-initiated template to a patient is sent only when LEADS.Consent_WhatsApp is true and Opted_Out is not (TEST_MODE sends and free-text replies in the 24 h window are exempt)
* W2 – Build New Lead: a lead created by an inbound WhatsApp message carries Consent_WhatsApp=true / Consent_Source=whatsapp-inbound (FLOWHQ_W2_IMPLIED_CONSENT=false turns this off)

### Step 10 — E-mail gateway: staff alert e-mail, optional patient acknowledgement

* W1: e-mail gateway: Email plan -> Has emails? -> Split emails -> Send email (SMTP credential "FlowHQ SMTP") -> Email result -> Run_Log; staff e-mail via FLOWHQ_ALERT_EMAIL_TO, optional acknowledgement via FLOWHQ_EMAIL_PATIENT_ACK (new lead + Consent_Email + not TEST_MODE + not quiet hours)

### Step 11 — W14 reconcile job, dead test node removed, operator notes rewritten

* removed "W2 – Test Cases" (reachable by no trigger; it fed W2 – Config and so would have bypassed the signature check)
* W14 – send-ledger reconcile (new section, every 15 minutes): stale "sending" -> "uncertain", old "uncertain" -> "unconfirmed", each logged in Run_Log; never re-sends

### Step 12 — Meta and AI provider base URLs are configuration

* W12 Meta base URL = FLOWHQ_WA_GRAPH_BASE_URL, W13/W9 AI base URL = FLOWHQ_AI_BASE_URL (defaults unchanged; https required except localhost mocks; refused by the config guards otherwise)

Step 06 also replaces the +91-only phone function in the 18 nodes that carried it (the W1 staff-alert node carries it as well: 19 copies, all identical and tested).

## Behaviour that changed on purpose (read before go-live)

| Before | Now | Why |
|---|---|---|
| W1 answered 200 immediately | answers after the lead is stored (200 ok / duplicate, 400 invalid, 404 unknown clinic, 500 if Grist fails) | no lost leads behind a 200 |
| W1 accepted any enquiry | needs the consent checkbox (`consent_whatsapp`); `FLOWHQ_W1_REQUIRE_CONSENT=false` accepts old forms but records "no consent given" | consent capture |
| any template to anyone | a business-initiated template to a patient needs `LEADS.Consent_WhatsApp = true` | consent gate (existing patients need a decision: see PRIVACY.md and `migrate-grist.js --backfill-legacy-consent`) |
| "Hello World" template in W3 / W5 / W6 | the approved templates in `templates/whatsapp-templates.md`; nothing is sent until they are approved by Meta | D01 |
| an unclear Meta answer counted as sent | it is "uncertain": not sent again, not reported as sent, settled by the delivery receipt or marked by W14 | M01 |
| Meta called without a record | a Send_Ledger row is claimed first (new Grist table: run `scripts/migrate-grist.js`) | no double sends |
| AI always possible if ai_mode on | external AI only if `FLOWHQ_AI_EXTERNAL_ENABLED=true`; patient identifiers masked | privacy |
| secrets and clinic ids inside the workflow | environment variables + n8n credentials created by `scripts/create-credentials.js` | no secrets in exports |
| webhooks answered by Caddy for the whole n8n | only `/webhook/*` is public; the editor is on an IP-restricted host | exposure |
| quiet hours switch ON | OFF | CLAUDE.md rule 5 |
| +91-only numbers | E.164 (India is the default for numbers written without +) | international patients |
